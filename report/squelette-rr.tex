\RRtitle{Amélioration des performances d'écriture des checkpoints pour l'application HPC Gysela}

\titlehead{Improving I/O Performances of HPC Application Gysela}

\RRresume{%
Ce rapport technique présente une étude approfondie visant à optimiser les performances d'I/O lors des phases de sauvegarde (checkpointing) du code de simulation gyrocinétique 5D Gysela, développé par le CEA. En utilisant le mini-app gys\_io, nous évaluons et comparons trois stratégies d'écriture parallèle (\textit{Single Shared File}, \textit{Subfiling} et \textit{File Per Process}) associées aux paramètres de configuration du système de fichiers parallèle (PFS) BeeGFS sur la plateforme Plafrim. Nos résultats mettent en évidence l'impact critique du nombre d'OST sur la bande passante, déterminent le nombre optimal de subfiles et démontrent la grande efficacité de la stratégie \textit{File Per Process} aux échelles étudiées.
}

\RRabstract{%
In modern High-Performance Computing (HPC) systems, Input/Output (I/O) performance represents a critical bottleneck for large-scale scientific simulations. As computational power scales towards exascale, storage bandwidth has not kept pace, creating a significant compute-to-I/O performance gap. Saving application states through periodic checkpointing is essential for fault tolerance, yet synchronous checkpoint writing halts computation and wastes expensive CPU/GPU hours.

This work focuses on optimizing the checkpointing performance of Gysela, a 5D gyrokinetic simulation code developed by the CEA for nuclear fusion research. Gysela generates massive datasets and relies on periodic checkpointing for execution restartability. Using gys\_io, a lightweight mini-application replicating Gysela's parallel 5D I/O patterns, we systematically evaluate three parallel I/O strategies—Single Shared File (SSF), Subfiling, and File Per Process (FPP)—alongside Parallel File System (PFS) striping configurations on clusters.
%Our experimental evaluation highlights a $\sim 5\times$ performance improvement when scaling Object Storage Targets (OSTs) from 1 to 8, identifies the optimal subfile configuration matching the physical OST count, and demonstrates that File Per Process achieves superior write bandwidth across evaluated node scales. Finally, we outline practical optimization guidelines and lay out future perspectives on tier-0 supercomputers.
}
